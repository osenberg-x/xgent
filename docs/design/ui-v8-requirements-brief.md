# XGent UI v8 · 需求简报（PRD）

> 状态：**提案**
> 时间：2026-10-16　基线 commit `d61e54b`
> 上游证据：[ui-v8-audit.md](../notes/ui-v8-audit.md)　技术设计：[ui-v8-layout-architecture.md](ui-v8-layout-architecture.md)　设计系统：[ui-v8-design-system.md](ui-v8-design-system.md)
> 视觉基线：**沿用 ADR-0014（Linear / v7）**，本轮不换色板、不换排版气质。

---

## 一、电梯陈述

XGent 是面向个人开发者的桌面端 AI 编码 Agent。v8 不改变它长什么样，而是**改变它能不能长成下一步该有的样子**：把界面从「五个系统各自写显隐、一个闭合枚举管五个互斥页签」的临时骨架，换成「一套分层与槽位规则驱动的可扩展工作台」，让 Git、MCP、插件面板、成本统计这些已经在路线图上的界面**有地方落地而不用再动布局代码**。

## 二、五维度定位

| 维度 | v7 落点 | v8 落点 |
|:---|:---|:---|
| 视觉 | Linear 暗色、明度阶梯、单一靛紫 | **不变**（只做排版密度与图标一致性收敛） |
| 结构 | 四列固定 + 一个闭合枚举侧区 | 四列 + **槽位注册表**驱动的侧区/浮层 |
| 交互 | 快捷键注册与分发脱节、浮层各自为政 | **模态栈单一权威** + 键盘路由 + 焦点可见 |
| 内容 | 助手消息扁平文本 | **Markdown/代码块富文本**，有序消息树 |
| 平台 | 等宽字体仅 macOS 成立 | **三平台一阶**（Windows/macOS/Linux）字体与 DPI 装配 |

## 三、问题陈述

开发者在 XGent 里让 Agent 干活时，界面会在四个时刻失信：

1. **看不见全部**——长会话里的工具结果、深目录树、diff、模型列表点了滚不动；长路径和文件名溢出或换行而不是省略（审计 C1/C3）。
2. **点不到该点的**——文件抽屉会盖住设置面板并吞掉点击，弹窗没有 Esc、没有点击外部关闭，开着设置时按 Esc 反而中断了对话（B1/B4）。
3. **读不懂回复**——助手输出一坨没有代码块、没有列表、没有加粗的纯文本，而代码恰恰是编码工具的主体内容（E1）。
4. **平台不对**——Windows 与 Linux 上「等宽」实际是 Inter 比例字体，终端格子、编辑器行号、diff 行全部对不齐（A1）。

更深一层：**今天的区域模型无法承载已经在路线图上的功能**。Git 已作为插件实现但没有 UI 入口（`SideViewContent` 是 closed enum，插件注册不进页签）；MCP、插件管理、成本统计都要新面板/新设置分区，而每加一个都要改五处 `Node.display` 写入点。上一轮 BSN 重构试图解决这件事，设计完被放弃，问题原样留存。

## 四、目标用户

- **主力**：个人开发者（本项目 MVP 定位），单项目单窗口长时间工作，键盘为主、鼠标为辅。
- **次要**：同项目多开客户端的开发者（daemon 共享配置与文件态），需要界面在两个进程里呈现一致的共享状态。
- **平台**：Windows / macOS / Linux **一阶同等**（本轮明确决定，非「Windows 兼容」）。

## 五、USP 与本轮取舍

XGent 的差异化是「实用优先 + 可扩展 + 轻量多开 + 陪伴感」。v8 服务前三个：**可扩展性从口号变成布局事实**。

明确**不做**（防范围膨胀）：
- 换视觉语言、改色板、改品牌（沿用 ADR-0014）。
- 亮色主题**实现**（本轮只把它需要的令牌结构与热驱动通路铺好，色板另轮）。
- 面板拖拽重排 / 自由 docking / IDE 级多窗口。
- BSN 声明式 UI 框架（理由见审计第七节）。
- 3D 视口、TUI、Web 端界面本体（3D 本轮**只做设计先行**，实现分段放行，见 [ui-v8-3d-viewport.md](ui-v8-3d-viewport.md)）。
- diff 算法升级（LCS/Myers，R3-12 保持独立账）。

## 六、北极星指标

**「新界面上手成本」**：一个此前不存在的功能面板（以 Git 源代码控制面板为探针），从写第一个 spawn 系统到出现在正确槽位、可切换、可键盘到达、可滚动、可截断、i18n 完整，需要的**改动文件数与新增代码行数**。

v7 现状基线：需触碰 `editor/mod.rs`（枚举 + 页签条 + 显隐）、`activity_bar.rs`（枚举 + 匹配）、`layout.rs`、`resize.rs` ≥ 4 个文件并新增两套互斥显隐逻辑。v8 目标：**注册 1 个面板描述符 + 实现 1 个视图模块**，不改任何既有布局文件。

辅助指标见第九节验收口径。

## 七、功能需求

编号 `U-xx`。验收标准全部可观察，禁止「优化」「改善」类不可判定措辞。

### U-01 跨平台字体与排版装配（P0，审计 A1/A2）

**作为** Windows 上的开发者，**我要** 终端与编辑器里的字符按等宽网格对齐，**以便** 我能靠列对齐读代码和表格输出。

- U-01.1 字体解析层按平台候选栈解析 `ui` 与 `mono` 两个槽位，任一平台都**必须**得到真实等宽资产；候选栈全部缺失时回退到内嵌的 OFL 许可等宽字体，**不得**回退到比例字体。
- U-01.2 终端单元格度量由「`font × 0.6`」经验值改为**实测字体 advance**（或用真实等宽 + 常量并附断言）。
- U-01.3 三平台各自的字体来源、路径与兜底行为在文档与运行时日志中可见。

**验收**：在三平台各启动一次，`tracing` 输出「mono 已解析为 \<实际家族\>」；截图比对终端 `ls -l` 输出的列对齐；自动化断言 `UiFonts::mono` 句柄 ≠ 默认句柄且指向已加载的等宽资产。

### U-02 分层与模态栈（P0，审计 B1–B4）

**作为** 用户，**我要** 弹窗永远在它该在的层、按 Esc 关掉最上面那层，**以便** 我不必猜现在什么东西挡着东西。

- U-02.1 五类浮层（基面 / 抽屉 / 下拉 / 提示 / 模态 / 通知）各占一段固定 `GlobalZIndex` 区间，集中定义，**禁止**在业务代码里裸写数字。
- U-02.2 模态栈为唯一权威：入栈/出栈驱动显隐，栈顶独享键盘；Esc 与点击外部按该层的 dismiss 策略生效。
- U-02.3 模态层开着时，全局快捷键（含 `chat.abort`）不得穿透到底层语义。
- U-02.4 提示（tooltip）脱离宿主子树，渲染在顶层浮层根，不受祖先 `Overflow::clip` 裁剪，并做视口边界翻转。

**验收**：打开设置面板后点文件抽屉钮 → 设置仍在抽屉之上且可点；任一浮层开着时按 Esc 关掉它且不影响对话；tooltip 在右缘按钮上不出窗、不被裁；grep 业务代码零裸 `GlobalZIndex(`。

### U-03 滚动契约（P0，审计 C1/C2/C4/C5）

**作为** 用户，**我要** 所有超出视口的列表都能滚，**以便** 长目录与长回复可见。

- U-03.1 提供唯一滚动容器构造器，内部保证 `OverflowAxis::Scroll` + 视口 + 内容 + 滚动条成套；**任何**需要滚动的区域只能用它。
- U-03.2 禁止 `Overflow::clip_y()` 与 `ScrollPosition` 并存（现有 9 处全部迁移）。
- U-03.3 区域填满一律 `flex_grow + min_height:0`，禁止在有兄弟节点的列里写 `height:100%`（消除 D2 的 38px 永久裁切）。
- U-03.4 长会话虚拟化启用（消费现成但零使用的 `xui::VirtualList`，R3-6）。

**验收**：对文件树/历史/命令面板/工具结果/确认弹窗 diff/编辑器正文/模型列表七处各塞入 200 条，滚轮与滚动条均可达末条；终端页签底部状态条在 700px 高的窗口内完整可见；自动化断言「内容高度 > 视口时末项可达」。

### U-04 文本省略原语（P0，审计 C3/E6）

- U-04.1 **自建**省略原语 `xui::Ellipsis`（行内尾省略）与 `xui::Clamp`（多行 clamp）。依据：bevy 0.20 **无 `TextTruncate`**，`TextBounds` 仅按字符硬裁且官方自陈不可靠（审计 C3）。供文件树、页签、状态栏、命令面板、工具参数统一使用。
- U-04.2 测量走 `TextPipeline::update_text_layout_info` → `TextLayoutInfo.size`（bevy 0.20 已有该 API，`bevy_text/src/pipeline.rs:485`），按 (原文, 可用宽, 字号) 缓存结果，避免逐帧重算。
- U-04.3 截断时完整值进 tooltip/详情，不丢信息。

**验收**：给定宽度不足的路径，出现 `…` 而非溢出或换行；hover 显示全路径；`xui::Ellipsis` 消费者数 ≥ 6；同一段文本反复改变宽度时测量不逐帧重跑（缓存命中可观测）。

### U-05 槽位注册表与可扩展区域模型（P0，审计 D1–D6）

**作为** 功能开发者（含插件作者），**我要** 向侧区注册一个页签，**以便** 新界面出现而不必改布局代码。

- U-05.1 `SideViewContent` closed 枚举被**描述符注册表**取代：每项带 `id`、`title`（i18n key）、`icon`、`order`、`slot`、可见性谓词。
- U-05.2 侧区、rail、设置分区、状态栏段、命令面板均可为注册目标（对齐插件系统 `ui_panel` 扩展点，D-P3）。
- U-05.3 可见性由注册表状态**单一系统**派生，废除五处各自写 `Node.display`（I3）。
- U-05.4 rail 活动项由注册表驱动，选中态从当前可见性**派生**而非独立存储（消除 D4 陈旧激活）。
- U-05.5 页签条只有一个所有者，消除双 tab 条与双返回按钮（D3）。
- U-05.6 分割模型支持声明式注册横向与纵向可拖分割，抽屉宽度可调。

**验收**：以 Git 源代码控制面板为探针——只新增 1 个注册项 + 1 个视图模块，不修改 `layout.rs`/`editor/mod.rs` 的枚举与页签条代码，面板即出现在侧区、可切换、可键盘到达；连点同一 rail 项两次后选中态与实际一致。

### U-06 富文本消息渲染（P0，审计 E1/E2）

**作为** 让 Agent 改代码的开发者，**我要** 回复里的代码块能一眼认出、能一键复制，**以便** 我不必从一坨纯文本里手工摘代码。

- U-06.1 消息成为**块序列**：段落、标题、行内码、代码块（带语言标签 + 复制）、有序/无序列表、引用、表格、链接、删除线。
- U-06.2 有序消息树：块顺序由状态权威 + 顺序键决定，流式增量插入正确位置，**禁止**命令式挪子节点（消除「流式文本排在自己工具卡之上」）。
- U-06.3 工具卡与消息同属一个有序序列，可折叠、状态可读（pending/running/ok/fail 走既有状态色）。
- U-06.4 渲染走增量而非整段重建（回应 BSN 评审 A-6 的性能担忧）。

**验收**：含 6 类元素混合的样张渲染正确、代码块底色与语法色符合 v7 令牌；边流式边插工具卡时顺序稳定不倒退；100 条消息的会话滚动帧时间不明显劣化（与 U-03.4 一并测）。

### U-07 输入与组合区（P1，审计 E3/E4/E5/F2）

- U-07.1 显式**发送/停止按钮**，状态可辨（可用/不可用/流式中），鼠标用户可完成完整往返。
- U-07.2 `@` 触发**内联补全浮层**（文件、符号、`@selection`），不再只在提交时静默解析。
- U-07.3 上下文集合成为独立模型：可增删、可持久化、显示 token 占比，不再只是打开 tab 的只读镜像。
- U-07.4 输入框自适应高度到上限后可内部滚，光标行始终可见。

**验收**：不碰键盘可完成一次发送与一次中断；输入 `@` 出现补全并可方向键选择；关闭某个上下文 chip 后其不再进入下一轮请求。

### U-08 快捷键与焦点闭环（P0 修死键，P1 建立机制，审计 F1–F4）

- U-08.1 **注册即生效**：分发表由注册表生成，编译或启动期校验「已注册 action 必有 handler」，杜绝 `palette.open_files`、`input.focus` 这类死键。
- U-08.2 焦点遍历顺序有意义（`TabIndex` 由布局顺序派生，不再全为 0）。
- U-08.3 焦点环可见，消费 `accent_glow`。
- U-08.4 快捷键标签与实际绑定单一来源，面板显示当前键位。

**验收**：启动期一致性检查通过且对现有 action 全绿；Tab 在设置面板内按视觉顺序遍历；任一控件聚焦时可见焦点环。

### U-09 主题令牌热驱动与双主题通路（P1，审计 G1–G5）

- U-09.1 `Theme` 由配置驱动、变更即时生效（复用已落地的设置热应用通路），不再有 Startup 一次性烘焙。
- U-09.2 令牌结构支持亮色预设（本轮**只铺结构**，亮色色板另轮）；半透明交互面在亮色下走黑色系（ADR-0014 裁剪 5）。
- U-09.3 字号/密度成为令牌刻度，支持紧凑/舒适两档。
- U-09.4 几何令牌化：消灭约 40 处魔法像素与绕过 `radius` 的圆角字面量；`820.0` 等重复常量归一；`px()` 单一来源。
- U-09.5 禁止业务代码 new `Theme::dark()`（修 `diff_view.rs:217`）。

**验收**：grep 业务模块零 `Theme::dark()` 现场构造、零 `Val::Px(<字面量>)` 于区域尺寸；切换密度档位全界面即时重排且无需重启。

### U-10 i18n 全覆盖（P1，审计 H1–H3）

- U-10.1 现存硬编码中文全部走 fluent：rail tooltip、顶栏、侧区页签（修 `let _ = loc;`）、状态栏占位、箭头字形。
- U-10.2 i18n 校验从「只扫 settings」扩展为**全模块扫描**，纳入 CI 口径。
- U-10.3 `xui` 的 `StringSource` 桥接真正被消费（R3-7 / D5）。

**验收**：英文语料下全界面无可读中文残留（自动扫描 CJK 码位，白名单显式声明）；rail/页签在中文界面文案正确。

### U-11 布局正确性自动化验证（P1，回应 I2 的「测不到」）

- U-11.1 新增**布局几何断言层**：区域分配高度 vs 视口内可见高度；无子节点越界；截断节点宽度 ≤ 父宽；浮层命中测试不被吞。
- U-11.2 覆盖当前完全无测的模块：chat、palette、confirm、status、topbar、resize、滚动、重叠。
- U-11.3 `ui-snapshot` 出图与原型逐状态人工对照（沿用 v7 M2-T6 工具）。

**验收**：上述缺陷每条有至少一个先失败后通过的回归测试；`cargo test --workspace` 全绿。

### U-12 路线图界面预留（P1，第四节）

本轮不实现这些界面，但**必须**验证它们能在槽位注册表上落地，避免又一代返工：

- U-12.1 Git 源代码控制面板（F-10 已有插件、缺 UI）。
- U-12.2 MCP 设置分区 + 连接状态段（F-13）。
- U-12.3 插件管理页 + 权限对话框（F-14 / D-P3）。
- U-12.4 成本统计分解面板（F-12 / R4-1 / OQ-10）。
- U-12.5 异步来源呈现规范：工具进度、索引进度、跨 IPC 取消均可由状态驱动渲染（`on_update` 未接通 D-P8 期间，UI 不得假设本地执行）。

**验收**：U-05 的 Git 探针通过；`on_update` 缺省时界面显示「执行中」而非空白或卡死。

## 九、范围外

插件任意自定义面板的**渲染沙箱**（WIT `ui.render` 具体执行）、BSN、docking 与拖拽重排、a11y 朗读、全局缩放（rem）、动画框架、宠物窗口本体（仅预留窗口层解耦）、3D/TUI/Web 界面、diff 算法、检索 B/C/D/E。

## 十、里程碑建议

顺序由依赖决定，细节与逐任务验收见 [ui-v8-tasks.md](../plans/ui-v8-tasks.md)：

```
M1 平台与令牌（字体/DPI/几何令牌/主题热驱动）
   └→ M2 层级与模态（分层常量、模态栈、tooltip 重定位、键盘路由）
        ├→ M3 滚动与省略（滚动契约迁移 9 处、TextTruncate、虚拟化）
        ├→ M4 区域模型（槽位注册表、派生可见性、rail 派生选中态、分割）
        └→ M5 会话内容（有序消息树、Markdown/代码块、输入区与补全）
             └→ M6 闭环与验证（快捷键注册校验、焦点遍历、i18n 全扫、布局几何断言）
```
