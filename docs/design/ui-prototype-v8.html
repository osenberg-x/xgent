现在 Theme 在 Startup 烘焙一次（layout.rs:60），spawn 时把色值取走就不再更新。改为 ThemeHandle { theme, generation }，节点带 Themed { role, gen }，重涂是属性写回而非重建节点。

// crates/xgent_ui/src/theme.rs
#[derive(Resource)]
pub struct ThemeHandle {
    pub theme: Theme,
    pub generation: u32,  // 每次热应用自增
}

#[derive(Component)]
pub struct Themed { pub role: ThemeRole, pub gen: u32 }

fn repaint_on_theme_change(
    handle: Res<ThemeHandle>,
    mut q: Query<(&Themed, &mut BackgroundColor)>,
) {
    if handle.is_changed() { // gen 落后才写，避免逐帧
        for (th, mut bg) in q.iter_mut() {
            if th.gen != handle.generation {
                bg.0 = handle.theme.resolve(th.role);
            }
        }
    }
}

  • 顺带：亮色主题只需换 raw 色板，不动面板代码。

注册表探针（M8-T1 验收）

每个按钮只向 PanelRegistry 追加一条 PanelDescriptor（id / slot / title_key / icon / order）。页签条、rail、显隐、键盘可达、滚动、截断、i18n 全部自动获得 —— 这就是「下一个界面不用再改布局」的可检验承诺。

终端双宽（A3，本审计新增）

A3：中文输出占约 2 格却按 1 格排版。即使 A1 修好字体，中文表格仍会错位 —— 必须按格数手工定位，不依赖跨字体连续排版（拉丁走 JetBrains Mono、中文走 Sarasa/Noto，无共享度量）。

图层检查器（B1 的分层常量）

开启检查器可在界面上看到六个静态层根的位置与 z 段。要点：业务代码禁止裸写 GlobalZIndex(<数字>)；静态类走常量，模态类由 ModalStack 按栈深分配 400 + depth × 8（预留 8 容纳模态内部下拉）。抽屉与下拉不带遮罩（非阻塞语义），只有模态带遮罩并独占键盘。
