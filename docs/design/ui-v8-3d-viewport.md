### 已核实的技术前提

- bevy 0.20 的 **`3d` 是默认特性**（`../bevy/Cargo.toml:136`），workspace 依赖未关闭默认特性 → `bevy_pbr` / `bevy_core_pipeline` 已在 `Cargo.lock`（`:1323` / `:749`）。**3D 不需要新增依赖，构建体积已付出**；新增成本只有运行时 GPU 与代码复杂度。

## 一、定位：3D 是面板，不是第二套界面

### 1.1 三种错误形态（明确不做）

| 形态                       | 为什么不做                                               |
| :----------------------- | :-------------------------------------------------- |
| **全屏宇宙 + 自由飞行**          | 六自由度飞行在编码工具里是负资产：迷失方向、晕动、键位与编辑器冲突；且它假设用户愿意「逛」而不是「找」 |
| **3D 代码墙**（把源码贴到空间里的平面上） | 3D 文本在非整数 DPI 下模糊、无法选中复制、排版成本高；**阅读永远回 2D**         |
| **独立 3D 窗口 / 第二应用**      | 与「轻量多开」冲突；跨窗口焦点、置顶、平台差异（K-04 同类问题）全部要重付             |

### 1.2 正解：`Slot::Center` 的一个注册面板

```
PanelDescriptor { id: "space", slot: Slot::Center, title_key: "panel.space", order: 10 }
```

- 与「对话」**同槽互斥**：中央列任一时刻只有一个 Center 面板可见，切换由注册表状态派生（U-05.3 的单一系统），不是新的 `if` 分支。
- 侧区（dock）与图标轨保持原样：3D 里选中文件 → 侧区编辑器打开该文件（2D 仍是阅读主场）。
- 两种呈现：
  - **并排**（默认）：3D 占中央列，侧区编辑器同时可见 → 「看结构 + 读代码」同屏。
  - **聚焦**（`Ctrl+Enter` 或双击空白）：3D 临时铺满 base 区，侧区隐藏；`Esc` 退回并排。聚焦是 Center 面板的一种布局态，**不是新层**。

> **对 v8 设计的具体增量**：`ui-v8-layout-architecture.md` 的槽位枚举原本只有 side / drawer / settings / status / palette。本轮已在 §3.1 补入 **`Slot::Center`** 与「同槽单活跃」规则（同日回写）。这条规则对后续「对话 / 空间 / 未来的任务看板」都成立，不是为 3D 特设。

### 1.3 渲染路径：离屏纹理，不是第二台摄像机直出

| 方案              | 做法                                                                        | 判定                                                |
| :-------------- | :------------------------------------------------------------------------ | :------------------------------------------------ |
| A 直出            | 3D 摄像机 `order: 0` 全屏清屏，2D UI 摄像机 `order: 1` + `ClearColorConfig::None` 叠加 | ❌ 3D 只能铺满整窗，无法裁剪进面板；UI 全屏容器会吞掉指针；清屏/排序与既有 2D 装配纠缠 |
| B **离屏到纹理**（推荐） | 3D 摄像机 `target: RenderTarget::Image(handle)`，UI 用 `ImageNode(handle)` 承载  | ✅ 布局系统仍是唯一权威（裁剪/滚动/模态栈语义全部适用）；视口可出现在任意槽位；无摄像机层叠问题 |
| C 独立子窗口         | 第二 window                                                                 | ❌ 平台差异 + 焦点 + 多开成本，且违背「3D 是面板」定位                  |

**B 的代价（必须写进预算）**：

1. 每帧一次额外 render pass；纹理尺寸随面板尺寸变化，需要 resize 策略（按 0.75 或 1.0 倍分辨率渲染再放大，见 §6 降级阶梯）。
2. **拾取不能依赖 `mesh_picking`**：UI 节点会先吃到指针。视口自己做「屏幕坐标 → 视口 UV → 相机射线」的映射，命中判定走 CPU（节点位置已知，投影后做半径判定），不为拾取建碰撞体。
3. 纹理是 `Handle<Image>`，主题切换时不清空（颜色来自材质 uniform，不重画纹理）。

## 二、空间语法：结构进空间，时间留在平面

### 2.1 四级 LOD（每级只回答一个问题）

| LOD    | 名称 | 视野      | 编码什么                      | 边                    | 标签          | 回答的问题                      |
| :----- | :- | :------ | :------------------------ | :------------------- | :---------- | :------------------------- |
| **L0** | 星系 | 整仓      | crate = 星团；半径 ∝ 代码量       | crate 依赖（Cargo.toml） | 13 个星团名     | 「这个项目的骨架是什么？谁依赖谁？有没有环？」    |
| **L1** | 星团 | 单 crate | 目录 = 轨道环；文件 = 星体；半径 ∝ LOC | `mod` / `use`（需语法解析） | 目录名 + 悬停文件名 | 「这个 crate 里哪块最重？哪些文件耦合最紧？」 |
| **L2** | 星体 | 单文件     | 符号 = 卫星（函数/结构体/测试）        | 引用/调用                | 符号名         | 「这个文件里谁调用谁？改动会波及什么？」       |
| **L3** | 阅读 | —       | **交回 2D 编辑器**             | —                    | —           | 「我要改代码」                    |

**硬规则：L3 不是 3D。** 双击文件星体 → 相机推近到 L2 上限后**淡出并打开 2D 编辑器**（150ms 交叉淡化）。在 3D 里渲染源码是本设计明确排除的项。

### 2.2 语义映射表

| 代码事实       | 空间编码                                       | 说明                                |
| :--------- | :----------------------------------------- | :-------------------------------- |
| crate / 目录 | 星团 / 轨道环                                   | 层级用「包含」而非「上下」——避免 3D 树状图那种上下翻飞的视角 |
| 文件         | 星体                                         | 位置由布局内核决定，**不按字母序**（字母序没有空间记忆价值）  |
| 代码行数       | 半径（对数刻度）                                   | 防止巨型文件吃掉整个视野                      |
| crate 依赖   | 星团间连线，方向用亮度渐变（亮端 = 依赖方）                    | 不画箭头（3D 里箭头在斜视角下不可读）              |
| `use` 关系   | 星团内细线，仅悬停/选中时显示                            | 全量常显会变成毛球                         |
| 未提交改动      | 星体外圈**白色细环**（`border_hover` 明度），环数 = 改动文件数 | **不用暖色**——暖色是陪伴专用（I-3）            |
| Agent 正在改  | 星体 `st_running` 靛紫脉冲（1.6s 呼吸）              | 复用状态语义 I-4，不自造                    |
| 工具失败/冲突    | 星体 `st_fail` 描边                            | 同上                                |
| 最近访问       | 星体基线明度略高（`text_dim` vs `text_muted`）       | 「我来过这里」比「它很重要」更有用                 |

### 2.3 时间不进 3D

**时间编码状态，空间编码结构。** 四维空间图（3D + 时间轴）在认知上不可读，且会让相机不断运动。做法：

- 底部一条 **2D 时间轴**（HUD，不是 3D 物体）：刻度 = agent 回合 / git 提交的合并序列。
- 拖动时间轴 → 3D **原地**更新状态（哪些星体亮起、哪些边出现/消失），**相机不动**。
- 默认停在「现在」；离开「现在」时视口边框变 `st_info` 细线 + 顶部显示「历史视图 · T-3」，防止误以为在看实时状态。

### 2.4 空间记忆优先于布局最优

这是本设计最重要的一条工程约束：

> **同一 commit + 同一图 → 同一坐标。禁止每次打开重新布局、禁止力导向逐帧漂移。**

理由：3D 的全部价值是「我记住了那个东西在左上」。如果每次打开位置都变，用户就退回搜索框，3D 沦为装饰。

实现约束（S0 内核必须满足）：

1. 初始位置由**确定性种子**生成：`seed = hash(节点路径)`，不用时间/随机数。
2. 力导向只做**有限轮预计算**（≤ 300 轮，收敛即停），产物是坐标快照，不是每帧模拟。
3. 增量更新时**已存在节点钉住**（anchor），只有新增节点在局部求解；删除节点不移动邻居。
4. 布局结果带 `layout_generation`，与图 `generation` 分离——图变了但布局没重算时，坐标仍然有效。

## 三、数据契约

### 3.1 类型（`xgent_core` 纯类型，无 Bevy）

```rust
/// 空间图快照。3D 只读投影，不持有真相。
pub struct SpatialGraph {
    pub generation: u64,
    pub nodes: Vec<SpatialNode>,
    pub edges: Vec<SpatialEdge>,
    pub clusters: Vec<SpatialCluster>,
}

pub struct SpatialNodeId(pub u32);

pub struct SpatialNode {
    pub id: SpatialNodeId,
    pub kind: SpatialNodeKind,     // Crate | Module | File | Symbol | External
    pub label: String,             // 展示名（不含路径）
    pub path: Option<PathBuf>,     // File/Module 才有
    pub cluster: ClusterId,
    pub weight: f32,               // LOC 的对数值，布局与半径共用
    pub status: SpatialStatus,     // Idle | Changed | Running | Failed
    pub anchor: Option<[f32; 3]>,  // 布局内核回填；None = 待求解
}

pub struct SpatialEdge { pub from: SpatialNodeId, pub to: SpatialNodeId, pub kind: EdgeKind, pub weight: f32 }
pub enum EdgeKind { DependsOn, Contains, Imports, ChangedTogether, AgentTouched }
```

要点：

- **不放进 `xgent_core` 的东西**：颜色、半径像素、相机参数、LOD 阈值。这些是视图策略，留在 `xgent_ui::space`。
- `SpatialStatus` 与既有工具状态语义对齐（`st_running`/`st_fail`），不新造状态机。

### 3.2 真相源

| 数据             | 真相源（已有）                                        | 刷新时机                 | 3D 的角色        |
| :------------- | :--------------------------------------------- | :------------------- | :------------ |
| crate 与文件树     | `xgent_context` 索引 / 文件树                       | 启动 + 文件监听事件          | 只读投影          |
| crate 依赖       | 各 `Cargo.toml` 的 `[dependencies]`（`toml` 已是依赖） | 启动 + `Cargo.toml` 变更 | 只读投影          |
| `mod`/`use` 关系 | **未定**（tree-sitter，D-06）                       | —                    | L1 暂缺，L0 不受影响 |
| 改动文件           | Git 插件（F-10）                                   | git 状态刷新             | 只读投影          |
| Agent 活动       | `ChatEvent` / 工具事件（已有）                         | 实时                   | 只读投影          |
| 时间轴刻度          | 会话回合锚点（已有）+ git 提交（F-10）                       | 实时                   | 只读投影          |

**3D 永远不成为任何数据的真相源。** 这一条与 `architecture.md` §10.3 一致，也是「可选插件层」能成立的前提：关掉 3D，功能零损失。

### 3.3 crate 归属（待决策 D-3D-02）

| 方案                                | 优点                                                          | 缺点                                           |
| :-------------------------------- | :---------------------------------------------------------- | :------------------------------------------- |
| **A 新 crate `xgent_spatial`**（推荐） | 纯 CPU 可 headless 测；不拖累 `xgent_context`；可选层可整体删除；未来 2D 依赖图复用 | 第 14 个 crate，workspace 再多一格                  |
| B 放 `xgent_context`               | 少一个 crate                                                   | 把「可选可视化」塞进「必需检索」，边界变浑；布局算法测试会污染 context 的测试面 |
| C 放 `xgent_ui`                    | 少一个 crate                                                   | 布局内核被迫依赖 Bevy，无法在 daemon/TUI 侧复用             |

推荐 A：`xgent_spatial`（deps: `xgent_core`，可选 `toml` 由调用方传入依赖清单，内核本身不读文件）。

## 四、视觉规范（在 v8 令牌内，不新增色相）

### 4.1 元素 → 令牌

| 元素        | 取值                                                         | 禁止                 |
| :-------- | :--------------------------------------------------------- | :----------------- |
| 视口底       | `bg #08090A`，中心略亮（径向 `surface` @ 6%）                       | 星空贴图、渐变背景图         |
| 星体（文件）    | 填充 `text_muted`，明度按 `weight` 在 `text_faint`↔`text_dim` 间插值 | 按目录分配色相（彩虹 = 噪音）   |
| 星团（crate） | 中心一个 `text_faint` 小核 + 极淡光晕（`accent_glow` @ 30%）           | bloom / 后处理辉光      |
| 依赖边       | `line` 白 @0.05，选中路径提升到 `border_hover` @0.14                | 彩色边、发光边            |
| 改动环       | `border_hover` 白 @0.14 细环                                  | 琥珀（陪伴专用）           |
| 运行中       | `st_running` 靛紫脉冲                                          | 自造「执行中」色           |
| 失败        | `st_fail` 描边                                               | 红雾、红色泛光            |
| 地面网格      | 白 @0.03，仅 L0 显示，可关                                         | 高对比科技网格            |
| 深度雾       | 雾色 = `bg`，`fog_start = 0.6 × dist`，`fog_end = 1.8 × dist`  | 蓝紫雾（改变色相）          |
| 标签        | 2D 叠加层（`ui_text` + `Ellipsis`），不建 3D 文本                    | `Text2d` / 3D 文本网格 |

**为什么标签是 2D 叠加层**：3D 文本要跟着透视缩放，小字模糊大字占位；而 2D 叠加层始终清晰、可复用 `Ellipsis` 与 tooltip、零额外渲染成本。做法：每帧把锚点投影到屏幕坐标，在视口上方的一个 UI 层里摆 label（限制同屏 ≤ 24 个，按距离与选中态排序）。

### 4.2 明度与可读性

- 视口内最高明度不得超过 `text_dim`（避免「发光的球」压过 2D 面板的正文）。
- 选中态：星体外扩 1 圈 `accent_interactive` 描边 + 2px `accent_glow`；**不做缩放弹跳**（会与「零投影、克制」气质冲突）。
- 空态：无节点时显示「索引构建中 42%」+ 骨架星云（`text_faint` @0.06），不是空白。
- 错误态：索引失败 → `st_fail` 边框 + 「无法读取项目结构」+ 重试按钮（T-6 三态规范）。

### 4.3 动效（v8 缺一层令牌，本文补）

| 场景        | 时长        | 曲线                |
| :-------- | :-------- | :---------------- |
| 悬停高亮      | 90ms      | ease-out          |
| 选中描边      | 120ms     | ease-out          |
| 相机聚焦飞行    | 320ms     | cubic ease-in-out |
| LOD 层级跳转  | 480ms     | cubic ease-in-out |
| 进入/退出聚焦   | 200ms     | ease-out          |
| 状态脉冲（运行中） | 1600ms 循环 | sine              |

**必须尊重「减少动态」**：系统开启 reduced motion 时，相机瞬移（0ms）、脉冲改为静态描边、LOD 跳转淡入淡出 120ms。这条应作为 `Theme`/`Settings` 的一个布尔令牌（`motion::REDUCED`），不是 3D 私有开关。

## 五、交互契约

### 5.1 相机：轨道，不是自由飞行

```
target: Vec3        // 注视点（星团或星体）
yaw / pitch         // 绕 target 的球面角，pitch 限 [-1.2, 1.2] rad
dist                // 200 .. 2400，指数缩放
```

- 拖拽 = 改变 yaw/pitch（左键）；滚轮 = dist（每格 ×0.9）；中键拖拽 = 平移 target（仅 L1/L2）。
- **无惯性滑行**：松手即停。编码工具里任何「还在动」的界面都在抢注意力。
- 双击星团 = target 飞向该星团 + dist → L1 区间；双击空白 = 回到 L0 全局。
- 窗口失焦 / 视口不可见 → 停止渲染循环（不是降帧，是停）。

### 5.2 输入映射

| 输入                  | 行为                               |
| :------------------ | :------------------------------- |
| 悬停 120ms            | 星体高亮 + 2D tooltip（名称 / 路径 / LOC） |
| 单击                  | 选中（右侧详情卡），不打开编辑器                 |
| 双击星体                | 推近 → 淡出 → 在侧区编辑器打开（L3 交棒）        |
| `Enter`             | 选中项的默认动作（文件 = 打开；星团 = 穿越）        |
| `Esc`               | 逐级回退：L2→L1→L0→退出空间视图             |
| `Tab` / `Shift+Tab` | 在当前 LOD 的可达节点间循环（按屏幕极角排序，方向可预期）  |
| `/`                 | 打开视口内搜索（复用命令面板的文件搜索数据源），选中即飞行定位  |
| `Ctrl+Enter`        | 并排 ↔ 聚焦                          |
| 方向键                 | yaw/pitch 步进 5°；`+/-` 缩放         |

**键盘可达性是硬要求**：3D 不能只有鼠标能玩。`Tab` 循环必须能在不旋转相机的情况下遍历当前层全部节点（选中时相机自动跟随但不旋转）。

### 5.3 与 v8 原语的关系

| 原语              | 3D 如何遵守                                                       |
| :-------------- | :------------------------------------------------------------ |
| 六静态层根           | 视口在 `BASE` 层内；HUD 是 BASE 的子节点；**不新建层**                        |
| `ModalStack`    | 3D 内不弹模态；文件冲突/工具确认仍走全局模态栈（视口暂停渲染循环）                           |
| `PanelRegistry` | 3D 是 `Slot::Center` 的一个描述符；可见性由 `derive_panel_visibility` 派生  |
| 主题热驱动           | 材质颜色每帧从 `Theme` 取（或订阅主题事件更新 uniform），**不烘焙**                  |
| `Ellipsis`      | HUD 路径、标签、详情卡全部走省略原语                                          |
| 拾取模型            | 视口 UI 节点 `Pickable::IGNORE` 不必要——视口自己处理指针；但视口外框可被拾取以支持 resize |
| 滚动契约            | 详情卡内容可滚时用 `ScrollFrame`，不自建                                   |

## 六、性能预算与降级

| 指标     | 目标                            | 说明                            |
| :----- | :---------------------------- | :---------------------------- |
| 可见节点   | ≤ 2,000（L0+L1）                | 超出则按 `weight` 裁剪，并显示「已省略 N 个」 |
| 可见边    | ≤ 6,000                       | 超出按权重采样，不做全量                  |
| CPU 布局 | ≤ 300ms / 全量，≤ 16ms / 增量      | 后台线程；主线程只收坐标                  |
| 帧预算    | 8ms（视口 render pass + 实例更新）    | 1080p、集显基准                    |
| 首帧     | ≤ 400ms（缓存命中）/ ≤ 1.5s（冷启动索引后） | 冷启动允许先显示星团骨架                  |
| 显存     | ≤ 64MB                        | 纹理 + 实例缓冲                     |

**降级阶梯**（按顺序触发，不询问用户）：

1. 渲染分辨率 ×0.75（纹理缩放）
2. 关闭地面网格与雾
3. 边改为「仅选中路径」（其余不画）
4. 标签上限 24 → 8
5. 停止 3D 渲染循环，显示静态首帧 + 「点击恢复」

每一级都必须在 HUD 角标显示当前档位（不静默降质）。

## 七、分期与验收


| 期 | 内容 | 前置 | 验收（可判定） |
|:---|:---|:---|:---|
| **S0 内核** | `SpatialGraph` 类型、crate 依赖提取、确定性布局、增量锚定、headless 测试 | 无（今天可开工） | ① 同一 commit 连续两次布局，坐标逐位相同；② 10k 节点全量 < 300ms；③ 增量加 100 节点，既有节点位移 = 0 |
| **S1 只读视口** | 离屏纹理、实例化星体/边、轨道相机、LOD0/L1、HUD 标签 | v8 M1（层根）+ M2（主题） | ① 2k 节点稳定 60fps（8ms 预算内）；② 主题切换后视口颜色随之变化、无需重启；③ 视口在 BASE 层内，抽屉/模态正确覆盖 |
| **S2 交互联动** | 悬停/选中/双击交棒、键盘遍历、搜索飞行、2D↔3D 联动 | v8 M5（`Slot::Center`）+ S1 | ① 全程键盘可完成「找文件→打开」；② 选中星体后编辑器打开同一文件；③ `Esc` 逐级回退不穿透到对话中断 |
| **S3 时空回溯** | 时间轴 scrubber、状态回放、历史视图边框 | S2 + D-3D-07 决策 | ① 拖到 T-3 时星体状态与当时 git 状态一致；② 相机不移动；③ 回到「现在」后状态完全恢复 |
| **S4 插件贡献** | 插件经 WIT 贡献节点/边（`spatial.nodes`） | 插件系统 `ui_panel` 落地 + S2 | ① 一个示例插件贡献 3 个节点并在 L0 可见；② 插件卸载后节点消失、布局不塌 |

**每期明确不做**：S0 不做渲染；S1 不做交互（只能转相机）；S2 不做时间；S3 不做编辑；S4 不做沙箱渲染。

## 十、风险

| 风险 | 表现 | 缓解 |
|:---|:---|:---|
| **新奇感衰减** | 第一周觉得酷，第二周回到文件树 | 3D 必须回答「谁依赖谁」这类 2D 难答的问题；否则砍掉 L2，只保留 L0 架构图 |

| **与 v8 并行返工** | 先做视口，v8 落地后重写接入层 | §8 闸门；S0 只做无 UI 内核 |

| **晕动 / 可访问性** | 相机飞行导致不适 | 无惯性、无自动旋转、reduced motion 瞬移 |
| **视觉越界** | 发光、彩色边、星空贴图破坏 Linear 气质 | §4.1 令牌表 + 评审时逐项对照 |
