# XGent v3 设计令牌文档（Design Tokens）

> 产出：设计系统专家（彩格调）｜输入：`ui-v3-requirements-brief.md`、`ui-prototype-v2.html`、`requirements.md`
> 落地对象：原型构建师（Bevy 渲染，非浏览器；令牌以 CSS 自定义属性形式给出，可直接平移为 Rust 常量）
> 设计哲学：**精密 · 克制 · 有呼吸感 · 有体温 · 状态可读**——冷电色管系统，暖色专供陪伴，绿色只做成功语义。

---

## 1. 候选设计系统推荐

从掌握的 71 套品牌级设计系统中，按「克制 + 有呼吸感 + 状态可读 + 精密工具类暗色」筛选，给出 3 个候选：

| 方案 | 设计系统 | 匹配度 | 核心特征 | 为何契合 XGent | 取舍 |
|---|---|---|---|---|---|
| A | **Linear** | ★★★★★ | 极暗近黑底（#0D0E10）、单一电蓝紫强调、发丝边框、状态色克制但精确、超低密度焦虑感 | 暗色精密工具的天花板；其「用最少的颜色表达最多状态」正是需求摘要的北极星；强调色与语义色严格分轨，呼应优化目标 #3 | 主参考 |
| B | **Raycast** | ★★★★☆ | 暖中性暗底、命令面板标杆、图标系统统一（1.75px 几何线性）、暖/冷分工清晰 | 命令面板（目标 #8）与「陪伴层暖色」的冷暖分工（目标 #2 品牌建议②）可直接借鉴；图标令牌基准贴近其 Phosphor 风格 | 辅助参考（图标 + 暖冷分工 + 命令面板） |
| C | **Vercel** | ★★★☆☆ | 极致发丝边框、近单一灰度、几乎无彩色、几何无衬线、大量留白 | 其「轻量、零彩色噪音」印证了 8pt 栅格与 hairline 边框方向，但过于 Web 营销风、缺少状态色体系，不宜作主参考 | 仅借鉴发丝边框与留白纪律 |

### 选定结论（可混合）

- **主参考 = Linear**：接管暗色深度阶梯、发丝边框纪律、强调/语义分离原则、状态可读的克制表达。
- **辅助参考 = Raycast**：接管图标令牌（1.75px 几何线性 / Phosphor 风格）、命令面板质感、以及「冷暖分工」的陪伴层暖色构想。
- **Vercel**：仅作为「边框 hairline + 留白」的纪律校验，不引入其彩色方案。

> 一句话：以 Linear 的冷电克制为骨架，以 Raycast 的暖冷分工与图标秩序为血肉。

## 2. 色彩令牌（CSS 自定义属性 + HEX）

```css
:root{
  /* ============================================================
     2.1 三层深度 + 对话区底 + 代码/终端最深底
     —— 沿用 v2 已验证的近黑蓝底，价值稳定；不堆第四层。
     ============================================================ */
  --bg:        #0B1120;   /* L0  全局最深背景（顶栏/活动栏/状态栏统一底） */
  --panel:     #131A2B;   /* L1  面板（侧栏/弹窗/命令面板/卡片底） */
  --elevated:  #1C2640;   /* L2  提升层（hover/选中/状态 pill/徽章） */
  --surface:   #0F1623;   /* L0.5 对话流底，略浅于 bg，给阅读区一点"浮起" */
  --deep:      #060A14;   /* L-1 代码块/终端/Diff 最深底，最大对比 */

  /* ============================================================
     2.2 边框丝线（三档独立变量，聚焦边框改用品牌冷电色，
          不再用绿色——这是与 v2 最关键的分离动作之一）
     ============================================================ */
  --line:        rgba(148,163,184,0.10);  /* 微弱分隔：面板内次级分割 */
  --line-strong: rgba(148,163,184,0.18);  /* 标准边框：面板外缘/卡片轮廓 */
  --line-focus:  rgba(45,157,255,0.55);   /* 聚焦边框：输入框/选中项/活动指示，冷电品牌色 */

  /* ============================================================
     2.3 文字四档（t0 主 / t1 正文 / t2 次要 / t3 弱化）
     ============================================================ */
  --t0: #F1F5F9;   /* 标题/用户主文字/强对比 */
  --t1: #CBD5E1;   /* 对话正文/通用文本 */
  --t2: #94A3B8;   /* 次要信息/状态栏/元信息 */
  --t3: #64748B;   /* 占位符/最弱提示/分隔文字 */

  /* ============================================================
     2.4 品牌主色（冷电色：cyan→indigo→violet 区间，
          electric/precise/calm；区别于 VSCode 绿、Cursor 蓝紫）
          保留一点青味呼应 logo 绿蓝渐变遗产，但本身是冷电蓝。
     ============================================================ */
  --brand:        #2D9DFF;   /* 主色：电蓝（cyan→indigo 偏青） */
  --brand-hover:  #54B4FF;   /* hover：更亮一档 */
  --brand-press:  #1E84E0;   /* 按下/active：更沉 */
  --brand-bg:     rgba(45,157,255,0.12);  /* 选中/激活底 tint */
  --brand-glow:   rgba(45,157,255,0.28);  /* 聚焦环/发光/呼吸态 */
  --brand-2:      #7C6CF5;   /* 辅助冷色：靛紫，专供品牌渐变第二端
                                （logo 渐变、宠物窗口呼应、装饰性渐变，不作状态） */

  /* ============================================================
     2.5 语义状态色（与品牌色彻底分离！）
          ★ 绿色 --ok 仅用于"完成/成功"，绝不兼任 CTA/聚焦/选中 ★
     ============================================================ */
  --ok:    #34D399;  /* 成功/完成/ok —— 纯绿，仅语义成功 */
  --ok-bg: rgba(52,211,153,0.12);
  --run:   #4C9BFF;  /* 运行中/流式/工具执行中（冷蓝，与品牌同温不抢戏） */
  --pend:  #F5B544;  /* 待确认/需用户授权（暖琥珀，界面级信号） */
  --pend-bg: rgba(245,181,68,0.12);
  --fail:  #F0616D;  /* 出错/失败/危险操作（红） */
  --fail-bg: rgba(240,97,109,0.12);
  --deny:  #64748B;  /* 已拒绝/已取消/中性终止（灰，复用 t3 语义） */

  /* ============================================================
     2.6 陪伴层暖色（专供陪伴锚点/状态徽章/宠物台词）
          —— 与冷色系统严格区分；一眼可辨"这是伙伴在说话"
     ============================================================ */
  --warm:      #FF8A5B;   /* 陪伴主暖色：暖珊瑚橙 */
  --warm-hover:#FFA279;
  --warm-bg:   rgba(255,138,91,0.12);   /* 陪伴锚点底 tint */
  --warm-glow: rgba(255,138,91,0.30);   /* 陪伴呼吸/脉冲光晕 */
}
```

### 色彩纪律（给原型构建师的硬约束）

1. **绿色 `--ok` 只用于成功语义**：完成态、ok 标、Diff 新增行、工具执行成功。任何 CTA、聚焦环、选中态、发送按钮都不得再用绿色——这些一律由 `--brand` 接管。
2. **冷色管系统/数据/工具执行**（`--brand` / `--run`）；**暖色 `--warm` 专供陪伴**（状态徽章、宠物台词、陪伴锚点）。两者不得互换。
3. **聚焦环永远用 `--line-focus`（品牌冷电）**，不用绿色、不用暖色。
4. `--brand-2` 仅用于品牌渐变装饰（logo、宠物窗口呼应），不参与任何状态判定。

## 3. 排版令牌

字体族（fallback 完整栈，跨平台 Windows/macOS/Linux 一致）：

```css
--font-ui:   "Inter","Segoe UI","PingFang SC","Microsoft YaHei","Hiragino Sans GB",system-ui,sans-serif;
--font-mono: "JetBrains Mono","Fira Code","Cascadia Code","SF Mono",Consolas,monospace;
```

三档字号·行高·字重（对应优化目标 #4 排版分级重做）：

| 档 | 字号 | 行高 | 字重 | 用途 |
|---|---|---|---|---|
| 正文 | 13.5px | 1.65 | 400 | 对话流正文、列表、通用文本 |
| 代码 | 12.5px | 1.6 | 400 | 代码块、终端、Diff、工具参数（等宽） |
| 元信息 | 11.5px | 1.4 | 500 | 状态栏、时间戳、pill、kbd、徽章标签 |

标题层级（克制，仅 3 级，避免 v2 的视觉噪音）：

| 级别 | 字号 | 字重 | 字距 | 用途 |
|---|---|---|---|---|
| H1 | 15px | 700 | -0.02em | 顶栏品牌名、弹窗标题 |
| H2 | 13px | 600 | 0 | 区块标题（大写小标签 style 用于侧栏 title） |
| H3 | 12.5px | 600 | 0 | 消息角色名、工具卡标题 |

> 对话流留白加大：消息行 `gap` 用 `--s3`，消息块间距用 `--s5`（20px），最大阅读宽度 `820px` 居中（沿用 v2 验证值）。

## 4. 间距 / 圆角 / 边框令牌

**8pt 栅格基础**（4px 为半档，保证精密工具的细调空间）：

```css
--s1:4px;  --s2:8px;  --s3:12px;  --s4:16px;
--s5:20px; --s6:24px; --s8:32px;  --s10:40px;
```

**圆角分级**（sm/md/lg/xl）：

```css
--r-sm: 4px;   /* 微元素：kbd、状态点容器、tag */
--r-md: 6px;   /* 默认控件：按钮、输入、图标按钮 */
--r-lg: 8px;   /* 卡片：代码块、工具卡、pill */
--r-xl: 12px;  /* 大容器：弹窗、命令面板、输入卡 */
```

**边框宽度**：

```css
--bw-hairline: 1px;   /* 所有分隔/外缘，统一发丝（Vercel 纪律） */
--bw-focus:    2px;    /* 聚焦环描边宽度（offset 2px，色 --line-focus） */
```

> 不引入 3px+ 粗边框——重边框会破坏"精密克制"。

## 5. 阴影 / 深度令牌（暗色下低饱和、低扩散）

```css
--shadow-flat:    none;                 /* 默认表面：靠边框分层，不靠阴影（轻量） */
--shadow-raised:  0 1px 2px rgba(0,0,0,0.40);   /* 卡片/下拉/hover 提升 */
--shadow-float:   0 12px 32px rgba(0,0,0,0.55); /* 弹窗/命令面板（浮动层） */
--shadow-hover:   0 1px 2px rgba(0,0,0,0.30), 0 0 0 1px var(--line-strong); /* hover 微抬 */
```

> 暗色下阴影只在浮动层（弹窗 z=50、命令面板 z=60）出现；常驻面板只用 `--line-strong` 分层，确保 NF-03「动画不阻塞、视觉负重轻」。

## 6. 动效令牌

```css
--dur-fast: 120ms;   /* 微交互：hover、图标态切换、待确认脉冲单帧 */
--dur-base: 180ms;   /* 主体过渡：聚焦环、边框、卡片展开 */
--dur-slow: 240ms;   /* 较大位移：弹窗/命令面板入场、分屏切换（仍 ≤ 轻量阈值） */

--ease:       cubic-bezier(0.4,0,0.2,1);     /* 标准 */
--ease-out:   cubic-bezier(0.16,1,0.3,1);    /* 入场/退场 */

--tf: var(--dur-fast) var(--ease);   /* 快捷：fast */
--tn: var(--dur-base) var(--ease);   /* 快捷：base */
```

**`prefers-reduced-motion` 降级约定**（呼应 NF-03 与优化目标 #5）：

```css
@media (prefers-reduced-motion: reduce){
  *,*::before,*::after{
    animation-duration:.01ms !important;
    animation-iteration-count:1 !important;
    transition-duration:.01ms !important;
    scroll-behavior:auto !important;
  }
}
```

> 所有动效 ≤240ms，主体 ≤200ms；流式光标、工具卡展开、待确认脉冲、状态过渡全部遵守上述降级。

## 7. 图标令牌（为 Bevy 侧留可直接映射清单）

```css
--icon-stroke: 1.75px;   /* 统一描边宽度（Raycast/Phosphor 基准） */
--icon-sm: 16px;         /* 列表项、状态栏、kbd 旁 */
--icon-md: 20px;         /* 活动栏、按钮内、消息头像旁 */
--icon-lg: 24px;         /* 空状态、区块大图标（极少用） */
--icon-style: "phosphor-geometric-linear";  /* 几何线性，圆角端点 linecap:round */
```

**Bevy 实现映射清单**（每个图标即一个 `IconToken` 枚举，描边/尺寸由上述变量驱动）：

| 用途 | 尺寸 | 落点 |
|---|---|---|
| 活动栏导航（文件/搜索/分屏/设置） | 20px | 活动栏 |
| 顶栏动作（新建/命令面板/设置） | 18–20px | 顶栏 |
| 工具时间线节点 | 14px | 对话流时间线 |
| 状态栏信号 / pill 图标 | 14–16px | 状态栏仪表 |
| 陪伴锚点表情图标 | 16–20px | 陪伴锚点 |
| 命令面板项图标 | 16px | 命令面板 |
| 侧栏文件树图标 | 15–16px | 侧栏 |

> 全程统一 `stroke-width:1.75`、`stroke-linecap:round`、`stroke-linejoin:round`；不混入填充图标（除 logo 与极个别品牌标记）。

### 新引入 v3 的关键落点汇总

- **陪伴锚点**（状态栏或输入卡旁 agent 状态徽章，覆盖 idle/思考/执行/待确认/出错 5 态；宠物关闭时优雅退化为纯状态指示器）：消费 `--warm*` + `--brand*/--run/--pend/--fail/--ok/--deny`。
- **状态栏仪表**（provider / token / 成本 / daemon 连接态，目标 #7）：消费 `--panel` + `--t2` + `--run/--pend/--ok` 状态点。
- **待确认脉冲**（界面级信号，非时间线黄点，目标 #6）：消费 `--pend` + `--pend-bg` + `--dur-fast` 脉冲动画。
- **导航减法**（6 层 → ≤3 层，目标 #2）：移除 viewtabs/sv-tabs 冗余层，活动栏 + 侧栏 + 对话流主区，令牌不限层。

## 9. 设计纪律（Cautions，给原型构建师）

- **Never**：用 `--ok` 绿做 CTA/聚焦/选中；用 `--warm` 暖色表达系统状态；新增未登记令牌（先来设计系统专家处校准）；用 ≥3px 粗边框或重阴影常驻面板；动效 >240ms 或不遵守 reduced-motion。
- **Prefer**：用 `--line-focus`（冷电）做所有聚焦；用 `--brand` 统一所有品牌交互；状态变化一律走语义色（ok/run/pend/fail/deny）；陪伴相关一律走 `--warm`；层级用边框+底部分层而非阴影。

---

> 令牌总数约 48 个（含尺寸/间距/字号档），每个都有存在理由，一一呼应需求摘要 8 条优化目标。原型构建师可直接将本文件 `:root` 块平移为 Bevy 侧 Rust 常量表。
